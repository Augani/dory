This is a bounded source audit and regression-test change, not P02 completion or Linux qualification. `compatibleV1` remains an engineering candidate. PAE, PSE and PGE stay unadvertised; this change does not alter `DoryX86CPUProfile.swift`.

Follow-up status and remaining blockers:

- **PAE load semantics, corrected in the run-17 source:** control state now retains all four PDPTEs. MOV CR3 and the specified CR0/CR4 transitions stage physical loads and reserved-bit validation before publishing controls or invalidating translations. Memory edits stay invisible until reload. Decode/import and dispatch validate the latch, and each paging unit and JIT uses the selected CPU physical width. Eighteen CPU/JIT and three machine test methods pass in combined run 17, including failed-load state preservation, all four selectors, reserved bits, repeated runs and both native tiers. Task-switch/VMX loading paths and full PAE feature qualification remain outside this correction; PAE stays unadvertised (§5.4.1).
- **Reserved paging bits, corrected in `84fcea664`:** PAE PDE/PTE entries now reject bits 62:MAXPHYADDR; legacy large-page PDEs reject bits 21:13 with PSE-36 unmodeled. Six focused methods cover selected physical widths, exact reserved-bit faults, nonpresent precedence, unchanged invalid entries and IA-32e ignored-bit controls; they pass in combined run 14. PDPTE latching is covered by the separate run-17 correction. PAT remains unadvertised, so PAT translation tests exercise the walker mechanism without qualifying a guest-visible PAT feature.
- **Control transitions and feature gates:** `writeControlRegister` accepts several CR4 features absent from CPUID and lacks the full PAE/long-mode/PCID transition checks. `writeModelSpecificRegister` accepts EFER.NXE independently of `executeDisable`. Test unsupported writes, unchanged state on failure, long-mode PAE invariants and PCID preconditions before promoting features. Broad invalidation is allowed; flushing global entries on MOV CR3 is not itself a PGE correctness defect (§5.10.4.1).
- **Privilege derivation, corrected in `3cb0ec8ab`:** interpreter and paging helpers now use CPL 0 in real mode and CPL 3 in virtual-8086 mode, independent of selector bits; VM is ignored in IA-32e mode. Eight focused methods pass in [run 13](evidence/p02-correctness-2026-09-04/review-through-run-13.json). Virtual-8086 port I/O consults the TSS bitmap even at IOPL 3. Paged implicit-supervisor TSS accesses, VME/flags behavior and virtual-mode segment/interrupt transitions still need separate work.
- **Descriptor-table stores:** the `.descriptorTable` interpreter case only checks privilege for loads. SGDT/SIDT stores lack the CR4.UMIP restriction and bypass the common operand-access path. Before UMIP or wider privilege qualification, test restricted stores, segment/canonical-address faults and no partial writes. UMIP is currently unadvertised and CR4.UMIP writes are rejected.
- **ISA feature execution:** conservative CPUID masks do not by themselves gate every decoded x87/SIMD/optional instruction. A feature-by-instruction audit and negative execution tests remain necessary; this paging change does not establish x86-64-v2 support.

Instruction-specific primary references are [SDM volume 2A](https://cdrdv2-public.intel.com/922480/253666-092-sdm-vol-2a.pdf), HLT, page 3-439, and [SDM volume 2B](https://cdrdv2-public.intel.com/922481/253667-092-sdm-vol-2b.pdf), SGDT pages 4-628/629, SIDT pages 4-654/655 and SWAPGS pages 4-696/697. The separate HLT/SWAPGS correction is recorded at `e167262fc`; descriptor-table access qualification remains open.
