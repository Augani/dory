## Earlier paging corrections

The primary reference is [Intel SDM revision 092, volume 3A](https://cdrdv2-public.intel.com/922487/253668-092-sdm-vol-3a.pdf), available through [Intel's SDM publication page](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html). Section numbering below is for revision 092.

| Source region | Correction and regression coverage | Reference |
| --- | --- | --- |
| `DoryX86Paging.swift`, `walkIA32e` | A 4 KiB PTE with PAT set retains a 4 KiB translation. Separate tests retain large-page PAT handling and reserved PML4/misaligned-large-page faults. | Tables 5-15 through 5-20 |
| `DoryX86Paging.swift`, `walkPAE`; `DoryX86Interpreter.swift`, `writeControlRegister` case 3 | Preserve CR3 root bits 11:5 for legacy PAE; the walker uses bits 31:5. Exercise three non-4-KiB-aligned roots and all four PDPTE selectors. Accept ignored low CR3 bits in legacy/IA-32e paging while retaining 4 KiB roots and reserved-high-bit/no-flush rejection. | §5.4.1, Tables 5-3/5-7/5-12; volume 2B, MOV to/from CR, page 4-32 |
| `DoryX86Paging.swift`, `walkPAE` | Derive permissions from PDE/PTE entries and leave valid PDPTE contents unchanged. Replace an existing invalid PDPTE fixture that used R/W and U/S. | §5.4.1, Table 5-8 |
| `DoryX86Paging.swift`, `walkLegacy32` | A PDE with bit 7 set still references a page table while PSE is clear; test both PSE settings. | §5.3 |
| `DoryX86Paging.swift`, `invalidate` | Evict every cached 4 KiB slice belonging to the addressed large page, including hot lookup slots. Test 2 MiB/1 GiB mappings, global/non-global entries and all three access kinds. | §5.10.4.1 and its large-page footnote |

`DoryX86PagingTests` contains 11 new test methods in this change, with 27 methods total. All 27 methods pass within [combined run 7](evidence/p02-correctness-2026-09-04/review-through-run-7.json), which records the exact source and complete results. This is the paging correction at commit `eb908d835`; later write-preflight work is recorded separately. The focused filter is `DoryX86PagingTests`.

Follow-up status and remaining blockers:

- **PAE load semantics, corrected in the run-17 source:** control state now retains all four PDPTEs. MOV CR3 and the specified CR0/CR4 transitions stage physical loads and reserved-bit validation before publishing controls or invalidating translations. Memory edits stay invisible until reload. Decode/import and dispatch validate the latch, and each paging unit and JIT uses the selected CPU physical width. Eighteen CPU/JIT and three machine test methods pass in combined run 17, including failed-load state preservation, all four selectors, reserved bits, repeated runs and both native tiers. Task-switch/VMX loading paths and full PAE feature qualification remain outside this correction; PAE stays unadvertised (§5.4.1).
- **Reserved paging bits, corrected in `84fcea664`:** PAE PDE/PTE entries now reject bits 62:MAXPHYADDR; legacy large-page PDEs reject bits 21:13 with PSE-36 unmodeled. Six focused methods cover selected physical widths, exact reserved-bit faults, nonpresent precedence, unchanged invalid entries and IA-32e ignored-bit controls; they pass in combined run 14. PDPTE latching is covered by the separate run-17 correction. PAT remains unadvertised, so PAT translation tests exercise the walker mechanism without qualifying a guest-visible PAT feature.
- **Control transitions, corrected in `31c215a97`:** CR0 reserved-bit handling, paging/cache combinations, IA-32e entry/exit and CR4.PCIDE preconditions validate before publishing state or invalidating translations. EFER.SCE/LME/NXE writes follow the selected profile; WRMSR invalidation reaches callers that supply only translated memory. Eleven focused methods pass in clean run 24, including failed-write state/TLB preservation and legal boot transitions. Implemented CR4 mechanisms remain testable without promoting their CPUID bits; the existing incoming-LMA equality policy remains explicit and unqualified. Broad invalidation is allowed; flushing global entries on MOV CR3 is not itself a PGE correctness defect (§5.10.4.1).
- **Privilege derivation, corrected in `3cb0ec8ab`:** interpreter and paging helpers now use CPL 0 in real mode and CPL 3 in virtual-8086 mode, independent of selector bits; VM is ignored in IA-32e mode. Eight focused methods pass in [run 13](evidence/p02-correctness-2026-09-04/review-through-run-13.json). Virtual-8086 port I/O consults the TSS bitmap even at IOPL 3. The run-19 follow-up gives TSS I/O-bitmap reads explicit implicit-supervisor paging, including VM86, SMAP/AC and distinct TLB identity. Seven focused methods verify precise page faults and unchanged ordinary operand privilege. Other descriptor/IDT accesses, VME/flags behavior and virtual-mode segment/interrupt transitions still need separate work.
- **Descriptor-table operands, corrected in the run-22 source:** LGDT/LIDT honor the effective 16-bit base width; SGDT/SIDT retain full stored widths. The full 6/10-byte explicit operand now receives segment/canonical range checks, protected-mode null-segment checks, mode-aware privilege/represented UMIP checks and atomic write preflight. Eight focused methods cover exact faults, cross-page stores and explicit SMAP/AC behavior. Alignment-check exceptions and wider descriptor/interrupt/task-switch semantics remain open; UMIP stays unadvertised and guest CR4.UMIP writes remain rejected.
- **LLDT/LTR descriptor loads, corrected in `938a83aa5`:** validate descriptor types, table bounds, presence and IA-32e upper fields with exact selector error codes. Descriptor reads and TSS busy-bit writes use implicit-supervisor paging; explicit selector operands retain their own privilege. Eight focused methods pass in run 28, including SMAP/AC separation, write-protected busy-bit updates and upper-half page faults. Loaded TSS/LDT base canonicality, overlapping fault priorities and full task-switch/interrupt behavior remain open.
- **Instruction-fetch boundaries, corrected in `ae471c9f8`:** speculative native decoding and byte providers decline on incomplete guest input. The interpreter supplies the precise fetch fault, while a previously completed native prefix remains published exactly once. Six methods exercise both JIT tiers, cold/cached blocks, page crossings and retry after mapping completion. Probe 8 subsequently reaches its seven-workload userspace receipt and ACPI S5.
- **SSE2 packed conversions, corrected in `27a84572d`:** eleven [conversion tests](../../dory-core-swift/Tests/DoryDBTX86Tests/DoryX86PackedConversionTests.swift) pass in run 32. They cover exact encodings, checked numeric results, rounding and precise exception status. This does not qualify all floating-point operations or justify a broader CPU profile.
- **ISA feature execution, partially corrected in `58928ec46`:** six [instruction-policy tests](../../dory-core-swift/Tests/DoryDBTX86Tests/DoryX86InstructionFeaturePolicyTests.swift) pass in run 34. Optional forms require their own represented feature before operand access; exact VEX encodings distinguish AVX and AVX2, while unsupported aliases remain `#UD` even under synthetic profiles. The remaining per-encoding x87/SIMD feature audit is separate work; no x86-64-v2/v3 qualification is established.
- **Legacy floating-point transfers, corrected in `2a22e9c6a`:** six [FX state-transfer tests](../../dory-core-swift/Tests/DoryDBTX86Tests/DoryX86FXStateTransferTests.swift) pass in run 35. FXSAVE/FXRSTOR touch only represented component spans, preserve software-tail/excluded slots and YMM upper halves, preflight writes, and preserve state on page faults or invalid MXCSR. Misalignment and segment-limit failures occur before transfer effects. Full x87 pointers/opcode/tag reconstruction and extended XSTATE qualification remain open.
- **SIMD execution controls, corrected in `af904e49a`:** nine [control-state tests](../../dory-core-swift/Tests/DoryDBTX86Tests/DoryX86SIMDControlStateTests.swift) pass in run 37. Legacy SSE and admitted VEX instructions validate CR0/CR4/XCR0 prerequisites before operand effects, retain `#UD`/`#NM` priority and mode rules, and reach data faults only when enabled. Both native tiers decline these forms without mutating state so the interpreter delivers the fault. Positive fixtures now explicitly enable the required state. This mechanism does not establish complete per-opcode feature masking or floating-point semantics.
